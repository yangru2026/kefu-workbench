## 花色素材页「加载太慢」修复：jsDelivr 301 是元凶（commit bae1214）

### 需求
茹姐截图反馈花色素材页「加载太慢，我想秒开」。

### 根因（实测锁定，链条完整）
1. `toCdnUrl()`（index.html ~11934 行）把图片 URL 输出成 `cdn.jsdelivr.net/gh/yangru2026/kefu-workbench@main/...`。
2. **jsDelivr 对本仓库的图片会返回 301**，Location 指向 `raw.githubusercontent.com`。
3. **`raw.githubusercontent.com` 国内直连极慢**——实测 `curl` 12s 超时失败（http=000）。
4. 首屏 20 张卡片图**每张都要吃一次 301 + 超时** → 页面长时间空白/图片逐个慢慢冒出来。
   - 对比实测：同源 `yangru2026.github.io` 直连同一张图 **200 OK，0.34KB→34KB，0.47~1.68s**。
5. 次要因素：`sw.js` 只处理**同源**请求（`isSameOrigin`），跨域的 jsDelivr 图片**根本没进缓存**，等于 SW 对图片完全没起作用。
6. 非瓶颈项（已确认无需改）：数据层早有秒显缓存（`kefu_cache_pattern_assets`，先渲染缓存再后台刷新）；
   卡片已分页（`PATTERN_PAGE_SIZE=20`）、已 `loading="lazy"`、首屏 6 张已 `fetchpriority="high"`；
   缩略图已是 34KB webp（thumb 目录 357 个文件）。

### 改动
1. **index.html `toCdnUrl()`**：改为输出**同源** `https://yangru2026.github.io/kefu-workbench/...`
   - 相对路径 → 同源绝对地址
   - 历史 jsDelivr 仓库地址 → 还原成同源（兼容 localStorage 旧缓存里可能存的旧值）
   - Supabase Storage / npm jsDelivr 地址 → 保持不动
   - 去掉原来 `url.includes('?')` 就原样返回的粗暴分支
2. **sw.js**：新增 `/images/` 图片缓存，策略 **stale-while-revalidate**（先返回缓存=秒开，同时后台静默拉新版）；
   - `IMG_CACHE = 'kefu-sw-img-v1'` **刻意不随 VERSION 变化**，SW 升级不会清掉用户已缓存的图
   - `IMG_MAX_ENTRIES = 800` 上限 + `trimCache()` 按插入顺序淘汰
   - `VERSION` v1 → v2（旧的 `kefu-sw-v1-*` 会被 activate 清理）
   - 注意 fetch 分支顺序：**isLib 必须排在 isImage 之前**（vendor 的 .js 不误判为图片）
3. `outputs/smoke-pattern-speed.js`：新冒烟脚本，mock 真实形态数据（thumb_*_url 用相对路径），
   断言 img src 无 jsdelivr、全部同源、**并用 `naturalWidth>0` 证明图片真实加载成功**。

### 验证
- `sw.js` node --check 通过；index.html 内联脚本 5 段 `new Function` 语法 0 错误。
- `toCdnUrl` 纯函数单测 6/6 通过（相对路径/已是同源/历史 jsDelivr/Supabase/npm 各自正确）。
- 无头冒烟：`imgCount=3`、`jsdelivrCount=0`、`sameOriginCount=3`、**`loadedOk=3`、`broken=0`**、无 pageerror、`swRegistered=true`。
- 推送 `b069e4b..bae1214` main。

### 教训
- **公共 CDN 不一定加速**：jsDelivr 的 gh 路径可能 301 到 `raw.githubusercontent.com`，
  该域名在国内基本不可用。给国内用户做 GitHub 托管资源，**同源 GitHub Pages 反而最稳**。
- **诊断顺序**：先 `curl -sI` 看状态码与 Location，再 `curl -sL -w '%{time_total}'` 看跟随重定向后的真实耗时——
  只看首跳状态码会漏掉"301 到坏域名"这种最坑的情况。
- **SW 只能缓存同源**：跨域图片进不了 SW 缓存，所以"把源改成同源"同时解决了可达性与可缓存性两件事。
- 部署后用户需 `Ctrl+Shift+R` 强刷一次（旧 index.html 在浏览器缓存里最多留 10 分钟）。
