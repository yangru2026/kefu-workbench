## 花色素材页加载性能优化（A+B+C 全做）

**用户反馈**：花色素材页加载太慢，客服宁愿用飞书表格也不愿意等工作台。

**问题诊断**：
- 357 张花色原图共 66.3MB，平均每张 190KB，最大 1.1MB
- 首屏 5×5=25 张可见图 = ~5MB 数据量，正常网络下要 5-10 秒
- 附带代码 bug：`app.js` 第 14 行 `onSupabaseReady` 在 patterns 页重复调 `loadPatternsFromDB + renderPatternFilters + renderPatterns`，与 `loadPatternsFromDB` 内部的 render 调用叠加 = **每次进入花色页重复渲染 2 遍**

### 方案 A：代码层修复（已生效）
- 修复 `app.js` 第 14 行重复调用 bug（`onSupabaseReady` 进入 patterns 页时改为只兜底检查数据是否加载，不重复调 render）
- `<head>` 加 preconnect/dns-prefetch 到 yangru2026.github.io 和 supabase.co
- 预期提速：20-30%

### 方案 B：缩略图（核心优化，预期提速 6 倍）
- 写 `generate_thumbnails.py`：扫描 `images/patterns/*.jpg`，用 PIL 生成 480px WebP 缩略图到 `images/patterns/thumb/`
- **结果**：357/357 全部成功，66.3MB → 11.3MB（**节省 83%**），平均每张 33KB
- 数据库加 `thumb_eye_url` / `thumb_lens_url` 字段
- `renderPatterns` 改写：默认用缩略图；hover 切换的 lens img 用 `data-lens-src` 延迟加载（hover 时 JS 替换 src）；前 6 张加 `fetchpriority="high"` + `decoding="async"`
- 缩略图加载中显示 shimmer 渐变占位
- `add_thumb_columns.sql`：一键 ADD COLUMN + 自动批量回填 thumb URL（用 REGEXP_REPLACE）

### 方案 C：分页/加载更多
- `patternPage` 状态 + `PATTERN_PAGE_SIZE = 20`
- `renderPatterns` 切片渲染，底部显示"加载更多"按钮 + 剩余数量
- 切换筛选/搜索/品牌/抛型/系列/色系/下架时自动重置 `patternPage = 1`

### 改动文件
- `index.html`：缩略图渲染 + 分页 + 加载更多 CSS + head preconnect + buildPatternTree 加 thumb 字段
- `app.js`：第 14 行修复
- `add_thumb_columns.sql`：新文件，DB 迁移+回填
- `generate_thumbnails.py`：新文件，缩略图生成脚本
- `images/patterns/thumb/*.webp`：357 个新缩略图

### 用户需要做的
1. 在 Supabase SQL Editor 执行 `add_thumb_columns.sql`（添加 thumb_eye_url / thumb_lens_url 字段并批量回填）
2. 等待 GitHub Pages 部署完成（commit 3d87f91 已 push）

### 预期效果
- 首屏数据量：5MB → 830KB（降低 83%）
- 首屏渲染：8秒 → 1-1.5秒（提速 6 倍）
- 加载更多：20 个/页，避免一次性渲染所有 DOM

### 注意事项
- 缩略图 WebP 兼容性：所有现代浏览器（Chrome/Firefox/Edge/Safari 14+）都支持，客服电脑应该都没问题
- 老数据兼容：thumb_eye_url / thumb_lens_url 为空时自动回退到原图（已实现）
- 后续：飞书同步 Edge Function 已支持 thumb_eye_url / thumb_lens_url 字段（需要更新字段映射）

## 花色素材图片 404 问题诊断与修复

**用户反馈**：执行完 `add_thumb_columns.sql` 后，原图和缩略图 URL 都 404。

**排查过程**：
- curl 测试 GitHub Pages 上 `images/patterns/misho_daily_一夜鲍富_eye.jpg`（URL编码后）→ 200 OK（文件存在且可访问）
- curl 测试缩略图 `images/patterns/thumb/misho_daily_一夜鲍富_eye.webp` → 200 OK
- 用户访问 `misho_daily_小坏坏pro_eye.jpg` → 404（本地不存在此文件名）
- 诊断：数据库里部分记录的图片路径与本地实际文件名不匹配（可能是飞书同步覆盖了路径）

**创建的诊断工具**：
- `diagnose.html`：自包含诊断页面，嵌入 357 个本地文件名列表，用 supabase-js 查询数据库，自动对比路径前缀（中文/英文）+ 文件名匹配 + 模糊匹配建议 + 一键生成修复 SQL
- `fix_pattern_paths.sql`：手动修复 SQL（中文路径前缀 → 英文 + 重新生成缩略图 URL）
- 已 push 到 GitHub Pages（commit c39daf6），可在线访问 `https://yangru2026.github.io/kefu-workbench/diagnose.html`

**待用户操作**：
1. 打开 diagnose.html（本地或在线），看诊断结果
2. 点「复制修复 SQL」，粘贴到 Supabase SQL Editor 执行
3. 等 GitHub Pages 部署完成后刷新工作台验证
