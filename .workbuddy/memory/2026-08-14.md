## 连带成交下拉选项"选完一会就消失"修复

**用户反馈**：客服在明细页选择店铺/产品类型/第一单状态后，过一会儿选项又变回"请选择"。

**根因**：
- `cross_sales` 表 RLS 策略中，普通客服只有 `SELECT` + `INSERT` 权限，没有 `UPDATE` 权限。
- 客服修改已有记录的下拉选项时，前端调用 `update()`，但 RLS 把非管理员的 UPDATE 静默拦截（返回 0 行、不报错）。
- `saveCSRow` 误以为保存成功，界面高亮；之后 Realtime 被触发重新拉取数据，又把空值渲染回来，表现为"选项消失"。

**修复**：
1. **新增 RLS 策略** `add_cross_sales_self_update_policy.sql`：
   - 普通客服可更新 `staff_name` 与本人 `profiles.name` / `profiles.real_name` 匹配的记录。
   - admin/leader 仍由原有策略管理全部记录。
2. **前端 `index.html`**：
   - `autoSaveCSRow`：修改已有记录前先做权限预判，非本人/非管理员直接提示，避免发无效请求。
   - `saveCSRow`：UPDATE 改用 `.select()`，检查返回数据是否为空；若为空则提示"⚠️ 保存未生效：你没有权限修改该记录"，不再显示假成功。

**用户操作**：
- 在 Supabase Dashboard → SQL Editor 执行 `add_cross_sales_self_update_policy.sql`。
- 客服 `Ctrl+F5` 强刷工作台后即可正常修改本人记录。

**提交**：`1fa38b8` fix: 放开客服更新本人连带成交记录权限，保存失败明确提示

## "显示全部"点完又自动折叠修复

**用户反馈**：连带成交明细点"显示全部"后，没几秒又折叠回分页。

**根因**：`renderCrossSales()` 每次整页重渲染（Realtime 同步 / 切筛选都会触发）都强制 `csCsPage = 1`，且调用渲染时不传"显示全部"标志；"显示全部"按钮只是一次性把所有行画出来、没有持久标记，所以 Realtime 一刷新就回到第一页（CS_PAGE_SIZE=120 条），视觉上即"折叠"。

**修复（index.html）**：
- 新增全局标记 `csShowAll`（默认 false）。
- `renderCrossSales()`：若 `csShowAll` 为真则 `csCsPage = ceil(rows.length/CS_PAGE_SIZE)` 保持展开，否则回到 1；两处 `renderCrossSalesEditableRows` 调用均传入 `csShowAll`。
- `loadAllCsRows()`：改为 `csShowAll = true; renderCrossSales();`，统一走重渲染路径，状态持久。
- 不自动重置：切换筛选/日期等仍保持"显示全部"，符合"别再折叠"诉求；数据量可控（全表仅 1505 条）。

**提交**：`2e605c4` fix: 显示全部后保持展开，Realtime重渲染不再自动折叠回分页

## 质检机制金额改为「显式映射」（用户纠正：日抛四盒99.9 与 99.7三幅 是不同产品）

## 16:10 质检页(cs-qc.html)真正根因：变量遮蔽导致整页崩溃（非 RLS/角色）

用户执行 v2 后首页恢复，但质检页仍"无权限、看不到明细"。经排查，**与 profiles RLS 无关**，根因在 `cs-qc.html` 第 187 行：

```js
var supabase = window.__csQcSupabase || supabase.createClient(SUPABASE_URL, SUPABASE_KEY);
```

`var supabase` 提升后**遮蔽**了 Supabase UMD 挂到 `window.supabase` 的库对象，右侧 `supabase.createClient` 实际指向 `undefined` → 抛 `Cannot read properties of undefined (reading 'createClient')` → **整段 `<script>` 在初始化即崩溃**，`supabase` 永远是 undefined。后续 `checkAuth()` 中 `supabase.auth.getSession()` 抛错被 catch，显示成假的"无权限"锁定。

主站 `index.html` 无此 bug（它把 `window.supabase` 库作为参数传入再 `lib.createClient`，未被局部 var 遮蔽）。

**修复**：
```js
var SB_NS = window.supabase;                          // 独立变量引用库，避免被遮蔽
var supabase = window.__csQcSupabase || (SB_NS && SB_NS.createClient ? SB_NS.createClient(SUPABASE_URL, SUPABASE_KEY) : null);
```

**附带修复**：`cs-qc.html` 的 `loadRecords` 里 `q.eq('team', scopeTeam)` 查询 `cross_sales.team`，但**该表无 team 列**（建表 SQL 第24-41行无此字段）→ 选具体组会报"列不存在"。已移除该数据库条件（组别下拉仅展示、不参与过滤，label 加 title 说明）。

**增强诊断**：`checkAuth` 在"未登录/角色不符"时显示登录邮箱与 `profiles.role` 原始值，便于万一仍是角色问题能一眼定位。

**Node 验证**：旧写法复现 `Cannot read properties of undefined (reading 'createClient')`；新写法正确产出 client 实例；内联脚本语法 0 错误。已 commit + push（git push origin main）。

**经验沉淀（重要，防复发）**：在浏览器 `<script>` 顶层用 `var x = ... || supabase.createClient(...)` 会遮蔽 UMD 全局 `supabase`，应用独立变量名引用库（如 `SB_NS`）。主站 index.html 用「传入库参数」模式规避，可参考。
