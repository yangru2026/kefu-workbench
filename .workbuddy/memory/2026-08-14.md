## 连带成交下拉选项"选完一会就消失"修复

**用户反馈**：客服在明细页选择店铺/产品类型/第一单状态后，过一会儿选项又变回"请选择"。

**根因**：
- `cross_sales` 表 RLS 策略中，普通客服只有 `SELECT` + `INSERT` 权限，没有 `UPDATE` 权限。
- 客服修改已有记录的下拉选项时，前端调用 `update()`，但 RLS 把非管理员的 UPDATE 静默拦截（返回 0 行、不报错）。
- `saveCSRow` 误以为保存成功，界面高亮；之后 Realtime 被触发重新拉取数据，又把空值渲染回来，表现为"选项消失"。

**修复**：
1. **新增 RLS 策略** `add_cross_sales_self_update_policy.sql`：
   - 普通客服可更新 `staff_name` 与本人 `profiles.name` / `profiles.real_name` 匹配的记录。
   - admin/leader 仍由原有策略管理全部记录。
2. **前端 `index.html`**：
   - `autoSaveCSRow`：修改已有记录前先做权限预判，非本人/非管理员直接提示，避免发无效请求。
   - `saveCSRow`：UPDATE 改用 `.select()`，检查返回数据是否为空；若为空则提示"⚠️ 保存未生效：你没有权限修改该记录"，不再显示假成功。

**用户操作**：
- 在 Supabase Dashboard → SQL Editor 执行 `add_cross_sales_self_update_policy.sql`。
- 客服 `Ctrl+F5` 强刷工作台后即可正常修改本人记录。

**提交**：`1fa38b8` fix: 放开客服更新本人连带成交记录权限，保存失败明确提示

## "显示全部"点完又自动折叠修复

**用户反馈**：连带成交明细点"显示全部"后，没几秒又折叠回分页。

**根因**：`renderCrossSales()` 每次整页重渲染（Realtime 同步 / 切筛选都会触发）都强制 `csCsPage = 1`，且调用渲染时不传"显示全部"标志；"显示全部"按钮只是一次性把所有行画出来、没有持久标记，所以 Realtime 一刷新就回到第一页（CS_PAGE_SIZE=120 条），视觉上即"折叠"。

**修复（index.html）**：
- 新增全局标记 `csShowAll`（默认 false）。
- `renderCrossSales()`：若 `csShowAll` 为真则 `csCsPage = ceil(rows.length/CS_PAGE_SIZE)` 保持展开，否则回到 1；两处 `renderCrossSalesEditableRows` 调用均传入 `csShowAll`。
- `loadAllCsRows()`：改为 `csShowAll = true; renderCrossSales();`，统一走重渲染路径，状态持久。
- 不自动重置：切换筛选/日期等仍保持"显示全部"，符合"别再折叠"诉求；数据量可控（全表仅 1505 条）。

**提交**：`2e605c4` fix: 显示全部后保持展开，Realtime重渲染不再自动折叠回分页

## 连带成交质检功能（仅admin）

**用户诉求（2026-08-14）**：需要一个质检连带明细功能（仅管理员开放）：
- 从 ERP 导出退款订单清单，用"原始订单号"去匹配明细的 first/second 订单号，命中即"退款"——不管第一单还是第二单退款都算不合格（不计入第二单销售额/提成）。
- 退款金额较小（≤¥10，如多付款退差价）标黄"退差价待确认"，大额退款直接判不合格。
- 按产品类型字符串里的机制金额（如"日抛四盒（99.9）"→99.9、"99.7三幅"→99.7）检查两单合计是否达标，偏低标"金额异常"。
- 管理员抽查不合格记录，确认无问题可手动改回"合格"（每条有「✅改合格」「❌保持不合格」+备注）。
- 原表金额/订单号一律不动，质检结果单独存字段；排名/提成统计做双版本（全部 vs 合格第二单金额，差值=被剔除金额），透明可对照，消除客服对"被删很多"的质疑。

**实现**：
- 新增 SQL `add_cross_sales_qc_columns.sql`：`qc_result`(pending/pass/fail_refund/fail_amount/difficulty_refund)、`refund_order_no`、`refund_amount`、`qc_amount_threshold`、`qc_note`、`qc_checked_at`、`qc_by`。沿用现有 RLS（admin 可写）。
- 前端 `index.html`：
  - 「··· 更多」菜单加 `id="cross-sales-qc-btn"`，仅 `role==='admin'` 可见（renderCrossSales 内显隐，leader 看不到，满足"只你开放"）。
  - 质检面板 `mod-cs-qc`：粘贴退款单文本（类型/原始订单/退款金额）→ `parseRefundText` 解析 → `runCsQcMatch` 调 `computeCsQc` 对当前范围（日/月+团队）逐条判定 → `renderCsQcList` 列出不合格项，每条可改合格/备注。
  - `saveCsQcResult` 批量 update 质检字段（admin 权限）；`exportCsQcResult` 导出质检结果 Excel。
  - 顶部汇总 `getCrossSalesGrandTotal` 双版本：全部第二单金额 vs 合格第二单金额（qc_result=pending/pass 才计入，其余按0），显示剔除差值；排名卡片同步显示合格金额。
  - `csRowHtml` 加质检徽章（红/橙/黄/绿），金额列不合格红框+「质检后¥0」。
  - 导出 Excel 加质检结果/退款单号/退款金额/机制金额列。
- 核心算法 node 验证通过：机制金额提取、退款解析（含表头跳过）、四类判定均正确。
