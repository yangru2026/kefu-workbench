## 5项工作台优化

### 1. 模板目标同步修复
- `openDailyForm()` 中无论是否有草稿，都先实时拉取最新模板
- 构建 `tplTargetMap` 映射，已有草稿时用最新模板目标覆盖旧目标，但保留已填的接待量/询单/支付数据

### 2. 日报结果卡片添加【售前】标签
- `renderDailyResult()` 顶部日期旁增加紫色"售前"标签，方便群里区分售前/售后

### 3. 成员管理支持修改姓名（花名）
- 新增 `updateMemberName()` 函数调用 Supabase 更新 profiles.name
- 新增 `editMemberName()` 交互：管理员点击名字 → 弹出输入框 → 回车/失焦保存
- 名字显示为虚线下面线样式，提示可编辑
- 预期修改：邓浩东→小咪，黄丽丽→小七，霍英姿→小火

### 4. 日报跟踪按排班表过滤当班人员
- `renderDailyTrack()` 完全重写：
  - 读取 config.json `scheduleData` 获取当日排班
  - 自动匹配 profiles 和排班表（支持精确+模糊匹配）
  - 只显示当班人员（排除休息），按组展示
  - 顶部横幅提醒未提交的当班人员
  - 统计卡片：当班人数/已提交/未提交
  - 排班中未注册的人也显示警告

### 5. 已提交日报按组汇总
- 跟踪页面底部新增"已提交数据汇总"区域
- 每组一个聚合表格：店铺名、接待量、询单、支付、转化率、平均目标、填报人数
- 数据跨客服汇总（同一店铺多人在不同组填报的各自独立汇总）

### Supabase Realtime 实时同步接入
- `subscribeDaily()` 增强：日报提交/修改时自动刷新跟踪视图（`renderDailyTrack()`）
- 新增 `subscribeTemplates()`：模板变更时自动 reload+re-render，客服和管理员立即看到最新
- 新增 `subscribeProfiles()`：成员名/角色/组别变更时自动刷新成员管理页
- `switchPage()` 和 `onSupabaseReady()` 中接入所有 5 个订阅通道
- 效果：不同电脑/不同客服之间的数据变更自动推送，无需手动刷新

## 排班姓名匹配+店铺延迟+卡片布局优化

### 1. 排班表支持真名/花名双向匹配
- profiles 表需增加 `real_name` 字段（text，nullable）
- `renderDailyTrack()` 匹配逻辑同时检查 `name`（花名）和 `real_name`（真名）
- 精确匹配优先花名，其次真名；模糊匹配也检查两者
- 成员管理页面新增「真实姓名」列，管理员可点击编辑
- 解决：李烁南(真名)=小南(花名)，马雷旭(真名)=小雷(花名)

### 2. 不同店铺类型显示不同数据延迟
- 新增 `getShopDelayDays(shopName)`：DY/抖音→1天，TM/天猫/PDD/拼多多/KS/快手→3天，其他默认3天
- 日报表单表头去掉固定"延3天"，改为通用提示说明各平台延迟规则
- 结果卡片底部标签按实际涉及的平台类型动态生成：
  - 例："⏳ 天猫/拼多多/快手 数据 = 3天前"、"⏳ 抖音 数据 = 1天前"
- 表头也去掉固定"延3天"小字

### 3. 日报结果卡片布局统一
- 顶部改为两行对齐布局：
  - 第一行左：日期，右：售前标签
  - 第二行左：名字·组别，右：总接待量+数字
- 视觉上更整齐统一
