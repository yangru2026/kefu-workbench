# 2026-08-30 工作日志

## AI 提问功能（方案确认 + 实现）

### 需求
工作台内嵌 AI 提问：客服遇到难回答的、专业的、或不知怎么组织语言的问题时可直接提问；管理员（杨茹）能看**所有人**的提问与回答记录用于监看；其他成员只能提问、只能看**各自**历史记录，互相看不到，也不知道存在监看。

### 关键约束与判断
- 工作台是纯前端 GitHub Pages，**大模型 API Key 绝不能写进前端**（会被从源码扒走盗刷）。→ 必须走 Supabase Edge Function，Key 存 Supabase Secrets。
- 已有基础可复用，无需新建登录体系：Supabase Auth；`profiles` 表含 `role`(admin/leader/其他)、`name`、`group_name`；`isAdmin` 沿用 `role in ('admin','leader')` 判断；已有 Edge Function 先例 `supabase/functions/feishu-sync/index.ts`。
- 权限必须落在**数据库层（RLS）**而非前端隐藏，这样改前端也绕不过。

### 用户选型（AskUserQuestion 确认）
- 大模型：**豆包**（火山方舟）
- 知识来源：**带上**工作台已有培训资料与话术（轻量检索后再回答）
- 提问次数：**不限制**

### 交付物
1. `create_ai_questions.sql` — `ai_questions` 表 + RLS 策略：
   - insert：仅 `auth.uid() = user_id`（伪造不了身份）
   - select：本人 或 admin/leader
   - update/delete：仅 admin/leader
2. `supabase/functions/ai-ask/index.ts` — 校验 JWT → 以用户身份建 client（RLS 自动生效）→ 用 bigram 关键词在 `training_knowledge` / `training_scripts` 检索 top6 → 调豆包 → 落库（含 user_name/group_name/total_tokens/latency_ms）。
   - 系统提示词内置红线：不承诺医疗效果、不用绝对化用语、眼部不适一律建议停戴就医、不确定就说不确定。
3. `index.html` — 侧栏新增「AI 提问」；新增 `#page-ai`（样式内联在该页内）；`switchPage` 加钩子；JS：`renderAiPage / setAiTab / loadAiHistory / renderAiHistory / submitAiQuestion / copyAiAnswer / formatAiAnswer`。管理员「全部记录」Tab 由 `isAiAdmin()` 控制显隐。
