### 关键技术决策：惰性触发
没有后台定时服务，自动确认靠「谁打开谁触发」：
客服打开链接 / 管理员打开质检工具 / 工作台首页加载 → 扫 `confirmed_at IS NULL` 的记录，
到期的补确认，剩 ≤12h 且没提醒过的发提醒。
效果等价于定时自动确认，统计不会卡住。

## 组长进质检工具被锁只读（commit `022b9f8`）

### 现象
杨茹截图：组长登录工作台进「质检」页，右上角显示「📖 只读模式」，「新增质检记录」按钮也是「🔒 只读模式」。

### 根因
之前为落实「组长仅保留质检报告 + 质检工具」裁权限时（commit `4292cdd`），漏改了父页面（index.html）传给 QC iframe 的角色判断：
- `switchPage` 中用 `currentUser && isAdminUser()` 决定 isQcMode
- `isAdminUser()` 只对 `role === 'admin'` 返回 true，对 `role === 'leader'` 返回 false
- 所以三位组长打开 QC 页时，父页面调用 `setQcMode(false)` 把 iframe 强制锁成只读
- 而且 QC iframe 内部的 `adminSetByParent` 标志被设了 true，**自己内部用 profiles.role 重新判断也改不回来**

### 修复（仅 index.html）
- `switchPage` 与 `onQcIframeLoad` 改用 `isQcRole()`（admin + leader 都 true）
- 顶部徽标文案分三档：
  - admin → `👑 管理员模式 · xxx@yy.com`
  - leader → `🛡️ 组长模式 · 可录入/删除质检`
  - staff  → `📖 只读模式`

### 验证
- inline script 语法 0 错
- `outputs/smoke-qc-leader-mode.js` 注入 4 套 profile 测三档判断：**10/10 断言全过**
- 已 push main，`70d107b..022b9f8`

### 复盘（重要）
`isAdminUser()` 和 `isQcRole()` 这两个权限函数在文件里并存，容易搞混。
以后改任何「判定能不能用某功能」的地方，先确认应该用哪一个：
- 仅管理员独享 → `isAdminUser()` / `isFullAdmin()`
- admin + leader → `isQcRole()`
- 普通以上 → `role !== 'staff'`
