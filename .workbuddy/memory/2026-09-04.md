## 修复：新增质检记录报错「null value in column "id" ... not-null constraint」（commit 444c2db）
- **现象**：杨茹截图反馈新增质检记录保存失败，toast 报 `null value in column "id" of relation "qc_records" violates not-null constraint`。
- **排查**：前端 `saveEdit` 的 `rec` 对象**不含 id**，插入时省略 id 本应由数据库自动生成 → 问题在表结构。仓库里两版旧建表脚本 `add_qc_tool.sql` / `ensure_qc_records_full_schema.sql` 把 `qc_records.id` 定义为 `id BIGINT PRIMARY KEY`（**无默认值无自增**）；9/3 重做的 `create_qc_schema_clean.sql` 才是正确的 `GENERATED ALWAYS AS IDENTITY`。结论：线上 qc_records 仍是旧定义（9/3 的 DROP/重建未完全生效或未跑）。
- **修复**：生成 `qc_fix_id_identity.sql`（幂等，可重复执行）：
  1. 查询当前 id 列定义；
  2. DO 块：`is_identity <> 'YES'` 时 `ALTER TABLE qc_records ALTER COLUMN id ADD GENERATED BY DEFAULT AS IDENTITY`；
  3. `setval` 把序列拨到 `MAX(id)+1`（防历史数据主键冲突）；
  4. 体检其余 qc_* 表（qc_images/qc_image_snapshots/qc_shares/qc_confirmations/qc_options/qc_staffs/qc_shops）的 id 是否同样缺失自增；
  5. BEGIN/ROLLBACK 干跑验证（不留数据）。
- **需杨茹执行**：Supabase SQL Editor 跑 `qc_fix_id_identity.sql`；第 3 步查询结果若还有其它表 `is_identity=NO 且 column_default 为空`，把表名发来我再补对应 SQL。
- **前端无需改动**（代码本来就不传 id）；无需强刷缓存。
- **执行反馈（杨茹跑完）**：第 4 步干跑报 `null value in column "shop"` —— 这证明 **id 自增修复已生效**（报错行 id=1788422349332759 已自动生成，不再是 null）；新报错是干跑行没带 shop，而线上表 `shop TEXT NOT NULL` 无默认值（与 clean 版 schema 有出入，线上表仍是旧结构）。已把验证 SQL 补上 shop（commit `4ad0008`）。
- **遗留确认项**：线上 qc_records 结构与 `create_qc_schema_clean.sql` 不一致（shop NOT NULL、疑似多余 created_at/updated_at 列），但功能可用；第 3 步其它 qc_* 表的体检结果杨茹尚未反馈，暂未发现其它表报错。
